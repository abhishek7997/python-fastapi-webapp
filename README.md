# FastAPI Crash Course – Issue Tracker

A small sample FastAPI app that exposes a REST API for managing issues (a minimal bug/task tracker). Issues are stored in a local JSON file, so no database is needed.

## Features

- CRUD endpoints for issues under `/api/v1/issues`
- Pydantic validation for request and response bodies
- Timing middleware that adds an `X-Process-Time` header to every response
- CORS enabled for all origins (for development)
- Interactive API docs generated by FastAPI

## Project structure

```
app/
├── main.py          # App setup, middleware, router registration
├── schemas.py       # Pydantic models and enums (IssueCreate, IssueUpdate, IssueOut)
├── storage.py       # JSON file persistence (data/issues.json)
├── routes/
│   └── issues.py    # Issue endpoints
└── middleware/
    └── timer.py     # Request timing middleware
```

## Getting started

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows (use `source .venv/bin/activate` on macOS/Linux)
pip install "fastapi[standard]"
fastapi dev app/main.py
```

The API runs at http://127.0.0.1:8000, with interactive docs at http://127.0.0.1:8000/docs.

## Endpoints

| Method | Path                    | Description        |
| ------ | ----------------------- | ------------------ |
| GET    | `/api/v1/issues/`       | List all issues    |
| GET    | `/api/v1/issues/{id}`   | Get an issue       |
| POST   | `/api/v1/issues/`       | Create an issue    |
| PUT    | `/api/v1/issues/{id}`   | Update an issue    |
| DELETE | `/api/v1/issues/{id}`   | Delete an issue    |

An issue has an `id`, `title`, `description`, `priority` (`low`, `medium`, `high`) and `status` (`open`, `medium`, `closed`).
